# Saturation Validation: Simulation vs. Real vLLM

Validates simulation results (BLIS/Vidur) against real vLLM performance using GuideLLM.

## Usage

```bash
python saturation_orchestrator.py \
  --results lowprefix_results.json \
  --config-name test_config_lowprefix.json \
  --simulator blis \
  --output-dir validation_results_blis
```

**For large models (34B+):** Add `--startup-timeout 600`

## Arguments

| Argument | Required | Default | Description |
|----------|----------|---------|-------------|
| `--results` | ✅ | - | Simulation results JSON file |
| `--config-name` | ✅ | - | Config name key in results file |
| `--simulator` | ✅ | - | Simulator type (blis/vidur) |
| `--output-dir` | ✅ | - | Output directory |
| `--vllm-port` | ❌ | 8000 | vLLM server port |
| `--startup-timeout` | ❌ | 300 | Startup timeout (seconds) |
| `--benchmark-timeout` | ❌ | 3600 | Benchmark timeout (seconds) |

## What It Does

1. Loads config and max QPS from results file
2. Starts vLLM server with simulated configuration
3. Runs GuideLLM benchmark at simulated max QPS (with 10% warmup)
4. Saves results to output directory

## Output

```
validation_results_blis/
├── vllm_server.log          # vLLM server logs
└── [GuideLLM files]         # Benchmark results (report.json, report.html, etc.)
```

## Troubleshooting

**Timeout on startup:** Increase `--startup-timeout 600` (large models need more time)

**Port in use:** Change port with `--vllm-port 8001` or kill existing server: `pkill -f "vllm serve"`

**CUDA OOM:** Reduce `gpu_memory_utilization`, `batch_size`, or `max_scheduled_tokens` in config

**Benchmark hangs:** Increase `--benchmark-timeout` or reduce `num_requests` in config
