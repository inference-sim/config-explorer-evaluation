# Saturation Validation: Simulation vs. Real vLLM

Validates simulation results (BLIS/Vidur) against real vLLM performance using GuideLLM.

## Usage

### Use Existing Deployment

```bash
python saturation_orchestrator.py \
  --results lowprefix_results.json \
  --config-name test_config_lowprefix.json \
  --simulator blis \
  --output-dir validation_results_blis \
  --deployment-name vllm-server \
  --namespace diya
```

### Create New Deployment

```bash
python saturation_orchestrator.py \
  --results lowprefix_results.json \
  --config-name test_config_lowprefix.json \
  --simulator blis \
  --output-dir validation_results_blis \
  --use-k8s \
  --namespace diya \
  --image vllm/vllm-openai:v0.14.0
```

## Arguments

| Argument | Required | Default | Description |
|----------|----------|---------|-------------|
| `--results` | ✅ | - | Simulation results JSON file |
| `--config-name` | ✅ | - | Config name key in results file |
| `--simulator` | ✅ | - | Simulator type (blis/vidur) |
| `--output-dir` | ✅ | - | Output directory |
| `--deployment-name` | ⚠️ | - | Existing deployment name (required if not --use-k8s) |
| `--use-k8s` | ⚠️ | False | Create new deployment (required if not --deployment-name) |
| `--namespace` | ❌ | diya | Kubernetes namespace |
| `--image` | ❌ | vllm/vllm-openai:v0.14.0 | vLLM container image (for --use-k8s) |
| `--startup-timeout` | ❌ | 600 | Startup timeout (seconds) |
| `--benchmark-timeout` | ❌ | 3600 | Benchmark timeout (seconds) |
| `--keep-deployment` | ❌ | False | Keep deployment (only for --use-k8s) |

## What It Does

**Existing Deployment Mode (--deployment-name):**
1. Finds pod from deployment name
2. Installs dependencies (pip, guidellm)
3. Starts vLLM server in pod
4. Runs GuideLLM benchmark in pod
5. Copies results back to local machine
6. Deployment/pod remains running

**New Deployment Mode (--use-k8s):**
1. Creates K8s deployment with H100 GPU affinity
2. Waits for pod to be running
3. Installs dependencies (pip, guidellm)
4. Starts vLLM server in pod
5. Runs GuideLLM benchmark in pod
6. Copies results back to local machine
7. Cleans up deployment (unless --keep-deployment)

## Troubleshooting

**Timeout on startup:** Default is 600s. Increase with `--startup-timeout 1200` for very large models

**CUDA OOM:** Reduce `gpu_memory_utilization`, `batch_size`, or `max_scheduled_tokens` in config

**Benchmark hangs:** Increase `--benchmark-timeout` or reduce `num_requests` in config

**Deployment not found:** Verify deployment name with `oc get deployments -n <namespace>`
